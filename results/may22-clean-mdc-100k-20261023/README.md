## Что исследовали

Один набор временных параметров и объёма — комплект 22 мая, детектор 221.
Истинные активности всех компонентов свежей пробы и памяти равны нулю;
остаётся детекторный фон. В сигнальных сериях вводится один свежий изотоп Xe.
Средние DETBK заданы вектором `[522, 854, 494, 66, 64, 89, 97]`.

Эффективности SAMPLE и GASBK одинаковы: Xe135 — 0,241169; Xe133 — 0,367784;
Xe131m — 0,233937; Xe133m — 0,233937. Это эффективности без branching.
Матрицы R, фиксированные ROI, времена, объём и конвенция радона сохранены
в `manifest.json`. Систематические ошибки не разыгрываются.

Совместная модель содержит 21 пуассоновский отсчёт SAMPLE/GASBK/DETBK и 17
оцениваемых параметров. Разыгрываются все три измерения, включая DETBK.
При обработке заново оцениваются все параметры. Сравниваются МНК и ММП
Пуассона. Вальд и профильные тесты не используются.

## Объём и порядок эксперимента

- **100 000** новых пустых проб для калибровки коэффициента `c`.
- **100 000 других** пустых проб для независимой проверки ложноположительной частоты.
- **20 000** новых проб на каждую сигнальную активность и изотоп при построении
  кривых мощности. Исходная сетка содержит четыре активности на изотоп —
  320 000 векторов; предусмотренные протоколом расширения учитываются отдельно.
- Для гистограмм при `A = 0` используются те же 100 000 проверочных проб,
  без нового розыгрыша и без отбора обнаружений.
- При `A = Ld95` генерируются **20 000** новых проб для каждого изотопа и метода,
  всего 160 000 векторов. Генерирующие значения берутся из зафиксированного
  нового анализа мощности и не перенастраиваются по этим сериям.

Без расширений это 680 000 новых формальных векторов наблюдений и 960 000
итерационных оценок MDC для гистограмм. Общие наблюдения используются обоими
методами там, где совпадает генерирующий сценарий. Старые случайные реализации
не входят в новые результаты. 128 технических проб исключены из статистики.

Исходное правило — `A_hat > Lc`. Lc вычисляется в каждой реализации по обычной
процедуре XeMat: неотрицательная вспомогательная подгонка, удаление целевого
свежего вклада из ожидаемого спектра и полная информация Фишера. Наблюдаемые
отсчёты не вычитаются. Память и остальные мешающие компоненты сохраняются.

Для подстройки используется `R = A_hat/Lc`, а `c` — порядковая статистика
ранга 95001 из 100 000. Коэффициенты замораживаются до чтения независимой
проверочной серии. После подстройки применяется строгое правило `R > c`.
Численный Ld95 находят по пересечению мощности 95%. Это оценка с погрешностью
Монте-Карло и интерполяции, а не математически точная константа.

В гистограммах показан **обычный итерационный MDC по каждому наблюдению**,
при alpha=beta=0,05, без множителя `c`. Центральные 95% значений показывают
разброс отдельных MDC и не являются доверительным интервалом истинного Ld95.
Контрольная мощность новых серий при фиксированном `A = Ld95` показана отдельно.
Полный протокол: [statistical_design.md](statistical_design.md).

## Полные данные и код

Для чтения отчёта эти файлы не нужны. Для исследования и воспроизведения:

1. Скачайте [архив документов, кода, сводок и отчёта](XeMat_May22_clean_MDC_100k_metadata.zip).
2. Скачайте **все части данных**, перечисленные в [DATA_ARCHIVES.md](DATA_ARCHIVES.md).
3. Распакуйте все ZIP в одну и ту же папку. Каждый архив — обычный независимый ZIP;
   специальный архиватор для многотомных архивов не требуется. Во всех частях
   одинаковая корневая папка `XeMat_May22_clean_MDC_100k`.

Части меньше 90 MiB каждая. Пары JSON/NPZ одной пачки не разрываются между
архивами. `package_index.json` содержит размеры и SHA-256 архивов;
`checksums.json` внутри metadata — контрольные суммы всех исходных файлов.
В каждой части есть собственный список содержимого в `package_parts/`.
Сырые `points/` на GitHub представлены только архивами, без повторной копии
тысяч отдельных файлов.

Основные материалы:

- `manifest.json`, планы и `run_lock.json` — физическая модель, генерационные
  параметры, seed и предварительно зафиксированный состав расчётов.
- `points/` — наблюдения, свободные и неотрицательные оценки, Lc, решения,
  итерационные MDC там, где они нужны, и явные признаки недоступных результатов.
- `calibration.json`, `calibration_bootstrap.npz`, `cutoff.json` — зафиксированные
  коэффициенты подстройки и bootstrap калибровки.
- `summary.json`, `analysis_bootstrap.npz` — частоты, кривые мощности, Ld95
  и интервалы, включая учёт внегридовых bootstrap-пересечений.
- `histogram_summary.json`, `histogram_values.npz` — статистика гистограмм
  и все значения MDC, включая NaN при недоступном результате.
- `verification.json`, `histogram_verification.json` — независимые проверки
  основной серии и гистограмм; `design_review.json` — проверка плана до расчёта.
- `technical/` и технический обзор — отдельная проверочная серия, исключённая
  из статистических выводов.

Ошибочные реализации не заменяются новыми и не объявляются автоматически
необнаружениями. Числа попыток, доступных результатов и пропусков сохранены
в сводках. Недоступность обычной ковариации свободного ММП учитывается отдельно:
она сама по себе не означает недоступность самостоятельного расчёта Lc/MDC.

## Единицы

В `points/*.npz` свежие объёмные активности, Lc и MDC заданы в **Бк/м³**.
В сводках, отчёте и `histogram_values.npz` — **мБк/м³**.
Полный вектор имеет координаты `[a_V; gamma; zeta]`: первые пять параметров —
свежие активности Rn222, Xe135, Xe133, Xe131m, Xe133m; следующие пять — память,
последние семь — ожидаемые отсчёты DETBK. Единицы объёмной активности нельзя
приписывать всем 17 координатам. Координата радона вспомогательная, в принятом
приближении старой модели.

## Проверка и повторное использование

После распаковки откройте терминал в папке `XeMat_May22_clean_MDC_100k`:

```text
python package.py --verify-only
```

Это проверка сохранённых байтов, полноты планов и успешных аудитов. Она использует
только стандартную библиотеку Python и не пересчитывает спектры. Проверяйте
архивное состояние до любых повторных расчётов. Для проверки самих скачанных
ZIP запустите `python package.py --verify-archives --archives-dir ПАПКА_С_ZIP`;
рядом с ZIP должен быть скачанный `package_index.json`.

Для анализа и построения отчёта нужен Python 3.11 или новее. Исходная среда:
Python 3.12.14, NumPy 2.3.5, SciPy 1.17.0, Matplotlib 3.10.8, ReportLab 4.4.9.

```text
python -m pip install -r requirements.txt
```

Просмотр массива MDC не требует ядра XeMat:

```python
import numpy as np
with np.load('histogram_values.npz') as data:
    values = data['may22_poisson_i4_null']  # Xe133m, A=0, мБк/м³
    print(np.nanquantile(values, [0.025, 0.5, 0.975]))
```

`analyze.py` пересобирает основную статистику из сохранённых наблюдений и оценок;
`histogram_analysis.py` — статистику MDC. Делайте это в отдельной рабочей копии:
они записывают выходные файлы, а контрольные суммы связывают этапы эксперимента.
`calibration.py --freeze` намеренно отказывается заменять уже зафиксированные
коэффициенты. Старую калибровку нельзя молча перезаписать после просмотра
проверочных результатов.

Для повторных подгонок нужен репозиторий `nicksidorov/first-project` на commit
[`69ff5a62ccaaddeb6372f7f003109ce5ff6cf333`](https://github.com/nicksidorov/first-project/commit/69ff5a62ccaaddeb6372f7f003109ce5ff6cf333).
**[Скачать исходники именно этой версии ядра ZIP](https://github.com/nicksidorov/first-project/archive/69ff5a62ccaaddeb6372f7f003109ce5ff6cf333.zip)**.
Эта версия опубликована в ветке `v86-joint-detbk`. Ветка отчётов
`xemat-may-ld-graphs` содержит другую версию кода; её текущий checkout нельзя
использовать вместо указанного commit для контрольных подгонок.

Архив отчёта сам по себе не содержит установленного ядра XeMat. Распакуйте
отдельный архив исходников и укажите папку с каталогом `xemat` через
`XEMAT_REPO`. Контрольные суммы нужных модулей сохранены в manifest.
Например, в Windows PowerShell:

```powershell
$env:XEMAT_REPO = 'D:\XeMat'
python verify_main.py
python verify_histograms.py
```

Эти аудиторы воспроизводят генерацию и контрольные подгонки, отдельно проверяют
формулы и сводки. Они требуют все распакованные части данных. `audit_design.py`
сохранён как исходный предрасчётный аудит и дополнительно использует прежнюю
папку исследования, указанную в нём; он не нужен для чтения новых результатов.

Чтобы повторить саму большую серию, используйте новую рабочую копию и сохранённые
планы `study.py --plan ... --workers 4`. В существующей папке уже готовые пачки
проверяются и пропускаются. Генерационные seed не меняются, ошибочные пробы
не заменяются. Подробная последовательность и условия независимости записаны
в протоколе; исходный архив оставляйте неизменным.
