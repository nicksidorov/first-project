## Модель из constants.py и трёх спектров

`process_prepared_measurement(None, sample_file=..., background_file=...,
detector_file=...)` собирает модель автоматически. Исходный IMS-парсер
не изменён; старый модуль расчётов не вызывается.

В V86 все три спектра участвуют в одной подгонке. Для `k` ROI и `n`
изотопных компонент модель имеет вид:

```text
x = [c_SAMPLE; d_GASBK; b_DETBK]
theta = [beta; gamma; zeta]
kappa_s = t_sl / t_bl
kappa_g = t_gl / t_bl
M = [[R_c, R_g1 @ F, kappa_s * I_k],
     [  0,     R_g2, kappa_g * I_k],
     [  0,        0,           I_k]]
mu = M @ theta
```

`zeta` — неизвестные **ожидаемые** отсчёты DETBK, а `b_DETBK` — реально
измеренные отсчёты. Их нельзя отождествлять. Фон не вычитается из наблюдений;
параметры `zeta` оцениваются вместе с пробой и памятью. В стандартной
конфигурации `k=7`, `n=5`: `x` содержит 21 отсчёт, `theta` — 17 параметров.

Исходные отсчёты трёх измерений считаются независимыми. Общие параметры
`zeta` создают корреляции **оценок** пробы, памяти и фона. Полная ковариация
включает статистическую неопределённость DETBK автоматически; отдельную
добавку этой же неопределённости вводить нельзя. При длительном DETBK
его влияние может быть небольшим, но модель не считает его точно известным.
Поле `JointModel.b` сохранено для прежнего API и в режиме V86 равно нулю:
это аддитивный сдвиг, а не обозначенный `b` в статье измеренный DETBK.

По `detector_id` из `#Header 3` выбираются предоставленные автором
`Rs_221/Rg_221` либо `Rs_222/Rg_222`. Все три номера должны быть известны
и совпадать; иначе `DetectorSelectionError` останавливает обработку,
а GUI показывает предупреждение с ролями файлов и их номерами. Подстановка
калибровки 221 при неизвестном или отсутствующем номере не выполняется.
Проверка применяется и к спектрам, обрабатываемым с готовой моделью NPZ;
в этом режиме сама M остаётся из NPZ. Без спектров NPZ проверка не нужна.
Старые имена `constants.Rs/Rg` сохранены как псевдонимы калибровки 221.
В отчёте присутствуют номера детекторов, источник калибровки и исходные
матрицы `R_c0/R_g0` выбранного детектора.

Строки Rs/Rg соответствуют ROI `[1,2,3,5,6,7,8]`, столбцы —
`[Rn222,Xe135,Xe133,Xe131m,Xe133m]`. ROI 4, 9, 10 остаются диагностическими
и не входят в совместную регрессию. При использовании границ из файлов
они должны совпадать с калибровочными границами `FIXED_ROI_TABLE`.
При фиксированных ROI эти границы переводятся в каналы каждого файла.
Опорные ROI `[2,3,5,6]` в SAMPLE/GASBK должны совпадать с калибровочными
границами даже в фиксированном режиме: эффективность из файла нельзя
применять к другой области. Для остальных областей и DETBK в фиксированном
режиме описания ROI из файла не используются. Пересечения после округления
каналов не допускаются.

Чувствительности ксенона вычисляются отдельно для геометрии пробы и памяти:
`I_c[j] = epsilon_SAMPLE[roi_j] * BR[j]`,
`I_g[j] = epsilon_GASBK[roi_j] * BR[j]`.
`BR[j] = ROI_INFO[isotope]['br']` — вероятность ветвления (branching ratio),
отдельная от эффективности. Для Rn222, Xe135, Xe133, Xe131m, Xe133m
соответственно используются 0.3700, 0.9020, 0.3700, 0.5400, 0.5577.
Использование эффективностей GASBK для памяти подтверждено автором.
При проверке названий изотопов допускается числовой суффикс IMS:
`XE133-10_81:30` распознаётся как `Xe133`. Признак изомера сохраняется:
`XE133M-10_81:30` соответствует `Xe133m` и не принимается за `Xe133`.
Парсер сохраняет исходную метку; нормализация нужна только для проверки.
Чувствительности и базовые отклики памяти считаются постоянными между
GASBK и SAMPLE. Для иных условий остаётся режим подготовленной модели.
Константа `C1=1` из старого кода не подменяет отношения `I_c[2]/I_c[4]`
и `I_g[2]/I_g[4]`.

Последовательность преобразований (индексы в формулах статьи от 1):

```text
C35(q,T) = (I3(q)/I5(q)) * lambda3/(lambda5-lambda3) * (G5(T)/G3(T)-1)
R_c  = Rs @ C(c,t_sr)
R_g1 = Rg @ C(g,t_sr)
R_g2 = Rg @ C(g,t_gr)
Bjj(tau) = exp(-lambda_j*tau)
B35(tau) = lambda3/(lambda5-lambda3) * (exp(-lambda3*tau)-exp(-lambda5*tau))
F = solve(H_g1, B @ H_g2)
Hjj = G_j(t_sr)/(t_sl*I_c[j])               # для Xe
H_g1,jj = G_j(t_sr)/(t_sl*I_g[j])          # для Xe
H_g2,jj = G_j(t_gr)/(t_gl*I_g[j])          # для Xe
Gamma35 = -lambda3/(lambda5-lambda3) * (exp((lambda5-lambda3)*t_p)*G5(t_a)/G3(t_a)-1)
G_p = diag(exp(lambda*t_p)); G_a = diag(G_lambda(t_a))
V0 = V_Xe / 0.087
T_V = G_a @ G_p @ Gamma @ H / V0
```

В совместимом API `G_s` обозначает `G_a` статьи, а `T_c` — `T_V`.
Калибровка возвращает оба имени каждой матрицы, NPZ принимает оба имени.
Это те же преобразования; повторно применять их не нужно.

Для образования дочери используются **реальные** длительности `t_sr,t_gr`,
а живые `t_sl,t_gl` входят в нормировку отсчётов. Дочерний пятый столбец
после поправки не перенормируется. `V_Xe` берётся из SAMPLE `#Processing`
в см³; `V0` имеет размерность м³. `air_volume` из `#Collection` не заменяет
извлечённый объём. В отчёт входят использованные преобразования.

**Радон:** функция `build_physical_matrices` по умолчанию требует
`radon_h={'sample':H11,'gasbk':H_g2_11,'sample_memory':H_g1_11}` в Бк/отсчёт
и `radon_mode='calibrated'`. Коэффициенты должны быть калиброваны для
соответствующих длительностей и начального состава радоновой цепочки.
Базовые радоновые столбцы при этом остаются из Rs/Rg.
Пользовательский режим трёх файлов по согласованию с автором по умолчанию
использует `radon_mode='legacy'`: `I_Rn=0.3*BR_Rn` и те же формулы G/(t_live I).
Это приближение старой калибровки, не полная калибровка цепочки из статьи;
предупреждение показывается и сохраняется. Оно влияет и на ксенон через F11.

Систематические относительные неопределённости берутся из **чисел**
`DELTA_EFF` и `DELTA_V_XE`: сейчас 0.001, то есть 0.1%, независимо от
устаревших комментариев 10%/5%. Они записываются как `delta_I`, `delta_V0`.
Дополнительная неопределённость формы Rs/Rg автоматически не моделируется.

## Координаты и ограничения

Входные `coordinates` задаются явно: `beta_gamma_zeta` означает `M=R_F`,
`a_V_gamma_zeta` означает `M=S_V`. `theta` всегда возвращается во входных
координатах; `physical_parameters` — в `[a_V;gamma;zeta]`, когда преобразование
известно. `Q=diag(T_V,I_n,I_k)` меняет только координаты пробы.
NNLS и неотрицательный ММП требуют неотрицательности **всех** компонент
`[a_V;gamma;zeta]`. При цепочках `beta>=0` не гарантирует `a_V>=0`.
Свободный МНК не ограничивает знаки параметров; свободный ММП ограничивает
ожидаемые отсчёты. В частности, его строки DETBK имеют `mu_DETBK=zeta`,
поэтому допустимость ожиданий уже запрещает отрицательную `zeta`.

Первая компонента статьи — радоновый мешающий вклад. Его активность в
детекторе имеет смысл, но первая координата `a_V` является вспомогательным
перенормированным параметром, а не атмосферной объёмной активностью радона.
Для стандартного порядка `[Rn222,Xe135,Xe133,Xe131m,Xe133m]` используйте
`mdc_component_indices=[1,2,3,4]`. Полный радоновый столбец остаётся в модели.

## Один квадратичный критерий

Оба квадратичных метода минимизируют
`(x-M theta)^T W (x-M theta)` в своих координатах. Веса по статье:
`w_i=1/x_i` при `x_i>0`, `w_i=1` при `x_i=0`. Это оценка пуассоновской
ковариации по наблюдению. Единицей заменяется только нулевая дисперсия;
исходные отсчёты не изменяются. Использование `1/(x+1)` для всех ROI изменило
бы критерий и здесь не применяется. Та же схема применяется к DETBK:
в стандартной модели веса рассчитываются для всех 21 исходных отсчётов.

Можно передать `weights` (положительный вектор или полную SPD-матрицу W)
либо `observation_covariance` (полную SPD-матрицу Ω). Эти параметры взаимоисключающие.
Размер вектора весов равен `3k`, полных матриц — `3k×3k` (обычно `21×21`).
При внешних весах статистическая ковариация предполагает `Ω=W^-1`.
Это ковариация **исходных** наблюдений `[c;d;b_DETBK]`. Не следует подставлять
сюда ковариацию фон-скорректированных SAMPLE/GASBK: это другие наблюдения.
Неопределённость общего фона учитывается оцениванием `zeta` в полной модели.

Решение использует отбеливание, масштабирование столбцов и SVD/устойчивый
ограниченный решатель, без явного обращения нормальных уравнений и без ridge.
Недостаточный ранг означает неидентифицируемость: конечные ошибки отдельных
параметров в этом случае не выдаются. Ковариация не домножается на reduced χ².

## Пуассоновские методы

Используются исходные целочисленные `x` всех трёх спектров, включая нули.
Детекторный фон входит в `mu` через оцениваемые параметры `zeta`.
Критерий `sum(mu-x*log(mu))` (без постоянного `log(x!)`) либо эквивалентный
девианс. При `x=0` вклад `x log(mu)` равен нулю. По прямому требованию
пользователя допускается `mu=0` при `x=0`; при `x>0` нужно `mu>0`.
Это расширяет строго положительную область, записанную в статье.
Недопустимые ожидания не подменяются положительными числами.
Ограничения на `mu` сохраняются и в свободном методе; искусственных границ
на величину параметров нет.

Свободный решатель использует SVD-базис, ограниченный — положительное
диагональное масштабирование, сохраняющее область физических параметров.
Для обычной неотрицательной S_V используется L-BFGS-B; для общей знаковой
матрицы сохраняются явные линейные ограничения. Сходимость подтверждается
проверкой допустимости и условий ККТ. Остаток округления на активной границе
может устраняться малой допустимой поправкой **параметров**, с повторным
вычислением mu и диагностическим сообщением; сами mu не обрезаются.

На активной границе используется уточнение Ньютона в касательном
пространстве: для строк ограничений E строится базис Z с `E @ Z = 0`,
а шаг определяется приведённой системой с матрицей `Z.T @ Hessian @ Z`.
Ограничитель длины шага учитывает остальные ограничения; округление вдоль
уже активной границы не должно блокировать полезное изменение параметров.
Отрицательные множители ККТ позволяют освободить ошибочно выбранную грань.
Границы ожиданий включаются только при `x=0`; нулевое наблюдение само по
себе не означает, что его оптимальное ожидание обязательно нулевое.
Для численного представления границы применяется запас порядка округления
в параметрах. Критерий по-прежнему вычисляется по исходным отсчётам и
`mu = M @ theta + b`, без псевдоотсчётов. Окончательная проверка ККТ
использует возвращаемые ожидания и физические параметры, в том числе
после устранения отрицательного остатка округления. Допуск сходимости
не ослаблен; остановка оптимизатора по малому шагу не заменяет эту проверку.

Ковариация свободного ММП вычисляется по ожидаемой информации Фишера
для **всех** `2n+k` параметров. Блок пробы выделяется после учёта памяти
и детекторного фона, а не из матрицы с удалёнными столбцами `zeta`.
При нулевом модельном ожидании обычная формула не определена.
Ковариации ограниченных оценок не выдаются как свободные ковариации:
в частности, активная граница имеет другое распределение оценки.

## Качество подгонки

В окне, TXT и CLI показываются `χ²/ν` для МНК/NNLS и приведённый девианс
`D/ν` для обоих пуассоновских методов. В JSON они находятся в `fit_quality`.
Исходный `FitResult.objective` сохраняет прежний смысл: взвешенная сумма
квадратов либо отрицательный логарифм правдоподобия без постоянного `log(x!)`.

Для МНК берётся фактически минимизированный критерий
`χ² = (x−mu)^T W (x−mu)`, включая переданные извне веса или полную ковариацию.
Для Пуассона рассчитывается
`D = 2 Σ[x_i log(x_i/mu_i) + mu_i − x_i]` по **исходным** отсчётам и полному
ожиданию с фоном. При `x_i=0` вклад равен `2mu_i`; при `x_i=mu_i=0` — нулю.
Нули остаются в числе наблюдений. При `mu≈x` используются `log1p` и ряд для
малой разности, чтобы не терять точность при вычитании больших чисел.

Нормировка `ν=N−rank` использует ранг, определённый решателем для полной
модели. В обычной схеме V86 это 21 наблюдение и 17 параметров, то есть `ν=4`.
Добавление семи наблюдений DETBK и семи параметров `zeta` сохраняет число
степеней свободы прежней модели.
Если `ν≤0`, приведённая статистика не определена: в окне/TXT ставится прочерк,
в JSON — `null`. Число положительных оценок не подменяет ранг модели.

Для NNLS и неотрицательного ММП `ν` явно обозначено как **номинальное**:
при активных ограничениях обычное χ²-распределение не гарантировано.
Значение около 1 служит ориентиром при достаточных отсчётах и корректной
модели дисперсий. При малых отсчётах, весах, оценённых по самим наблюдениям,
или граничных ожиданиях `mu=0` такой ориентир требует осторожности.
Даже в асимптотическом случае при `ν=4` стандартное отклонение `χ²/ν`
равно `sqrt(2/ν)≈0.71`, поэтому небольшое отличие от 1 не означает плохую модель.
Диагностика не масштабирует погрешности активностей и не меняет L_C/MDC.

## Активности и MDC

Из построителя калибровки или NPZ передаются H, Γ, G_p, G_a, V0 либо T_V
(совместимые имена G_s и T_c). Вся цепочка и
распространение ковариаций выполняются явными матричными операциями.
H переводит амплитуды beta в Бк, T_V — в Бк/м³.
Пересчёта мБк в ядре нет; нельзя применять поправки повторно к уже
преобразованной физической модели.

В `ActivityResult` доступны имена V86 `a_V`, `T_V`, `K_A_V_stat`,
`K_A_V_sys`, `K_A_V`, `std_A_V`, `correlation_A_V`. Это свойства, ссылающиеся
на прежние поля `a_c`, `T_c`, `K_A_c_stat`, `K_A_c_sys`, `K_A_c`, `std_A_c`,
`correlation_A_c`. В JSON пока сохраняются прежние имена полей; их значения
для модели V86 имеют смысл объёмных активностей `a_V` и их неопределённостей.

Для MDC одна свободная подгонка задаёт оценку для решения об обнаружении,
одна полная неотрицательная — физический нулевой спектр. Из него вычитается
только свежий вклад проверяемого нуклида. Память того же нуклида и весь
детекторный фон сохраняются. Строки GASBK и DETBK при таком вычитании
не меняются. Исходные наблюдения `x` также остаются неизменными.
Столбцы из S_V не удаляются, мешающие параметры не подгоняются заново
на итерациях. Для полной матрицы `S_V` размера `21×17`:
`K_i(L)=[S_V^T diag(1/(mu0+L*s_i)) S_V]^-1`,
`LC=z_(1-alpha)*sqrt(K_i(0)[i,i])`,
`MDC=LC+z_(1-beta_II)*sqrt(K_i(MDC)[i,i])`.
Обнаружение: **свободная оценка `a_V[i]>LC`**, а не сравнение с MDC.
Нулевой спектр должен быть строго положительным, матрица полного ранга.
Недоступность или несходимость расчёта сообщается явно, без `abs` или
подмены MDC запасным числом.

MDC использует модельную пуассоновскую ковариацию статьи при фиксированной
калибровке, с совместным оцениванием пробы, памяти и `zeta`. Статистическая
неопределённость DETBK уже входит в `K_i(L)`. Систематические погрешности
чувствительностей и объёма, добавляемые к погрешностям активностей,
в стандартный расчёт LC/MDC не добавляются.
Переданная для МНК внешняя ковариация
не подменяет `K_i(L)` автоматически; её дополнительные источники ошибок
потребуют отдельного расширения модели MDC.

## Формат NPZ

Массивы загружаются с `allow_pickle=False`. Для V86 при передаче
`R_c,R_g1,R_g2,F` нужны `kappa_s`, `kappa_g` и координаты
`beta_gamma_zeta`; для `a_V_gamma_zeta` передайте готовую `M=S_V`.

| Поле | Форма и назначение |
| --- | --- |
| `M` | `(3k,2n+k)` совместная матрица V86; альтернатива `R_c,R_g1,R_g2,F,kappa_s,kappa_g` |
| `x` | `(3k,)` исходные целые отсчёты `[SAMPLE;GASBK;DETBK]`; можно заменить тремя IMS-файлами |
| `b` | `(3k,)` нули; для V86 можно не указывать. Измеренные отсчёты DETBK находятся в `x` |
| `n_sample_parameters` | целочисленный скаляр, число первых параметров пробы |
| `n_detector_parameters` | целочисленный скаляр `k`; при явных координатах с `zeta` может определяться по размеру M |
| `coordinates` | Unicode-скаляр `beta_gamma_zeta` или `a_V_gamma_zeta` |
| `T_V` (или `T_c`) | `(n,n)` невырожденный перевод beta в a_V; при указании обоих имён матрицы должны совпадать |
| `H`, `Gamma`, `G_p`, `G_a` (или `G_s`), `V0` | подготовленные преобразования активностей; при указании обоих имён `G_a` и `G_s` должны совпадать |
| `weights` или `observation_covariance` | внешние веса или ковариация для квадратичных методов |
| `isotope_names`, `parameter_names` | строки для отчёта |
| `sample_roi_numbers`, `gasbk_roi_numbers`, `detector_roi_numbers` | одинаковый порядок ROI всех трёх блоков; `roi_numbers` — общий порядок |
| `mdc_component_indices` | явно выбранные индексы ксенона с нуля, только из блока пробы |
| `alpha`, `beta_ii` | вероятности ошибок, по умолчанию 0.05 |
| `mdc_mode` | `iterative` по статье; `fixed` — отдельно помеченное приближение постоянной дисперсии |
| `delta_I`, `delta_V0` | дополнительные относительные стандартные неопределённости |

Числа, единицы, порядок компонент и ROI являются частью физической
спецификации файла. Пример содержит учебные матрицы и не заменяет калибровку.
В готовой M фоновые блоки должны иметь вид `κ_s I`, `κ_g I`, `I`,
а строки DETBK — нулевые отклики пробы и памяти. При использовании
реальных файлов коэффициенты κ должны соответствовать их живым временам.
ROI должны быть непересекающимися для независимого пуассоновского критерия
и модели MDC статьи. Адаптер трёх файлов проверяет это после калибровки,
округления и ограничения каналов ровно как в сохранённом парсере; общий
конечный канал также означает пересечение. Полные перекрывающиеся ROI
старой таблицы (например, ROI 4 вместе с 5–8) выбирать совместно нельзя.
В NPZ с готовыми `x` непересечение является обязанностью составителя модели.

### Совместимость с прежними подготовленными моделями

Координаты `beta_gamma` и `a_c_gamma`, `n_detector_parameters=0` сохраняют
прежний режим: `x=[c;d]`, `mu=M theta+b`, а `b` — известный аддитивный фон.
Для построения такой M используются `R_c,R_g1,R_g2,F` без κ. Здесь `T_c`
переводит beta в `a_c`, физические параметры имеют вид `[a_c;gamma]`.
Старый NPZ не превращается в модель V86 автоматически. Этот режим нужен
для воспроизводимости старых расчётов; обычная обработка трёх спектров
из `constants.py` использует совместное оценивание DETBK по V86.
