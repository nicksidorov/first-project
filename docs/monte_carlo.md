# Эксперимент: соблюдают ли Lc и MDC заданные вероятности?

Этот модуль проверяет статистическую процедуру XeMat на повторных
искусственных измерениях. Сохранённая версия до экспериментов отмечена
меткой `stable-before-experiments-2026-10-15`; разработка эксперимента
ведётся в ветке `experiment-monte-carlo`.

## Запуск в приложении

1. Выполните обычный расчёт по SAMPLE, GASBK и DETBK (либо готовой NPZ-модели).
2. Нажмите **«Монте-Карло: Lc / Ld…»**. Используется последний рассчитанный
   результат, включая его ROI, эффективности, матрицы и фон.
3. Выберите изотоп ксенона с рассчитанным MDC и семейство оценивателей:
   МНК/NNLS или пуассоновское МП/МП с неотрицательностью.
4. Задайте число повторов **на каждый из двух сценариев** и seed генератора.
   Для первого знакомства достаточно 1000 повторов. При вероятности 5%
   случайная стандартная ошибка такой частоты около 0,69 процентного пункта;
   для 10 000 — около 0,22 п.п. Доверительный интервал выводится в результатах.
5. Запустите расчёт. Его можно остановить, сохранив выполненную часть.
   Сохранение TXT даёт читаемый отчёт, JSON — также матрицы, истинную смесь,
   оценки и пороги отдельных повторов для дальнейшего анализа.

Для сравнения двух семейств оставляйте одинаковыми исходный расчёт, seed
и число повторов. Модуль сохранит одну истинную смесь и одни случайные
отсчёты. Изменится процедура оценивания. Смена семейства в эксперименте
не пересчитывает исходную смесь и исходный MDC другим методом.

## Истинная модель эксперимента

Обозначения сохранены из статьи:

| Величина статьи | Переменная модуля |
|---|---|
| `z_+ = [a_c,+; gamma_+]` — неотрицательная оценка исходной смеси | `reference_positive_physical` |
| `S_c = M Q⁻¹` — отклик в физических координатах | `S_c`, `model.physical_matrix` |
| `z_0` — та же смесь, но `a_c,i = 0` | `reference_null_physical` |
| `mu_i^(0) = b + S_c z_0` | `reference_null_mu` |
| `mu_i(A) = mu_i^(0) + A s_c,i` | `reference_signal_mu` при `A=MDC` |
| `L_C`, `L_D=MDC` исходной модели | `reference_L_C`, `reference_MDC` |
| Свободная оценка и пересчитанный LC в каждом повторе | `free_activity_samples`, `L_C_samples` |

Исходная неотрицательная смесь определяется семейством обычного расчёта:
NNLS для МНК, неотрицательное пуассоновское МП для Пуассона. При обнулении
проверяемого изотопа удаляется только его физическая активность **пробы**.
Его память `gamma`, радон, другие изотопы и все столбцы матрицы остаются.
Обнулять `beta` вместо `a_c` при цепочке Xe133m → Xe133 неправильно.

Оба сценария используют одни фиксированные мешающие активности:

- **A=0**: проверяемого изотопа в пробе нет. Частота обнаружений оценивает
  вероятность ошибки первого рода, сравниваемую с `alpha` (обычно 5%).
- **A=MDC**: истинная активность равна исходному `L_D`. Частота обнаружений
  оценивает мощность, сравниваемую с `1-beta_II` (обычно 95%).

## Что происходит в каждом повторе

1. Генерируется каждый исходный ROI SAMPLE и GASBK:
   `x* ~ Poisson(mu_i(A))`. Нулевые отсчёты сохраняются. Нельзя разыгрывать
   очищенные от фона или округлённые активности вместо исходных отсчётов.
2. Заново оценивается полная свободная модель и вспомогательная модель
   с неотрицательными **физическими** параметрами. Мешающее присутствие
   задано для генерации, но при обработке его значения считаются неизвестными.
3. Из новой вспомогательной оценки строится новый нулевой спектр и `L_C`.
4. Обнаружение проверяется строго по `a_c,free > L_C` своего повтора.

Для МНК стандартные веса `1/max(x*,1)` пересчитываются по новым отсчётам.
Если исходная модель задавала внешние веса/ковариацию, они сохраняются.
Это всё ещё опыт с независимыми пуассоновскими отсчётами: дополнительные
корреляции из внешней ковариационной модели при генерации не воспроизводятся.

Внутри повтора не требуется заново решать итерацию MDC: она не участвует
в решении об обнаружении. Используется общий расчёт LC из основного ядра.
Исходный MDC рассчитывается в исходном режиме (`iterative` либо `fixed`).

## Как читать результаты

Показаны число выполненных попыток, успешных обработок, ошибок,
обнаружений и 95%-й точный биномиальный интервал Клоппера—Пирсона.
Пять процентов не обязаны получиться точно даже при идеальном уровне:
сама оценка частоты имеет случайную погрешность.

Если были ошибки решателя или расчёта LC, они не заменяются отсутствием
обнаружения и не перерозыгрываются. Основная доля `K/N_success` и её интервал
в этом случае **условны на успешной обработке**. Дополнительно выводятся
границы `[K/N_attempted, (K+N_failed)/N_attempted]`: возможная доля среди
всех попыток, если все ошибки означали бы соответственно отсутствие или
наличие обнаружения. Это диапазон из-за ошибок, не доверительный интервал.

Остановка оставляет частичный результат. Если остановиться, увидев
желаемую частоту, обычная интерпретация 95%-го интервала уже неверна.
Для окончательной оценки лучше заранее выбрать число повторов и закончить их.

В TXT дополнительно показана доля решений с **фиксированным исходным LC**
на тех же успешных повторах. Это вспомогательное сравнение: основной тест
проверяет именно процедуру с пересчётом LC на каждом измерении.

## Что этот опыт проверяет

Это параметрическая проверка при **одной выбранной** смеси, фоне и калибровке.
DETBK, матрицы R, эффективности, объём, времена и систематические
неопределённости не разыгрываются. Результат относится к одному изотопу,
а не к событию «обнаружен хотя бы один из четырёх».

Если данные генерировать и обрабатывать с одной и той же неверной R,
эксперимент сам по себе не обнаружит её ошибку. Для проверки устойчивости
к ошибкам калибровки нужно отдельно задать разные истинную и используемую
при обработке матрицы. Это следующий вид эксперимента.

Первая версия проверяет мощность в точке исходного MDC. Она **не выдаёт
эмпирический L_D**: для его определения нужна серия активностей и поиск
уровня, где вероятность обнаружения достигает `1-beta_II`.

## Независимый пример с точным ответом

Пусть один ROI, известный фон `b=1`, чувствительность `s=1`. Тогда
свободная оценка `a_hat=X-1`, а `LC=z_0.95=1.64485362695`.
Правило обнаружения эквивалентно `X>=3`.

При нулевой активности `P(Poisson(1)>=3)=0.08030139707`, то есть **8,03%**,
хотя в асимптотической формуле LC задано 5%. Это следствие дискретности
и малого числа отсчётов, а не ошибка генератора Монте-Карло.

Для `alpha=beta_II=.05` формула статьи даёт
`LD=2*z_0.95+z_0.95²=5.995250708`. Точная мощность в этой точке — **97,03%**.
Такой пример позволяет проверить реализацию независимо от её собственных
формул подгонки и не требовать от корректного кода заведомо неверных 5%/95%.

Ядро для собственных сценариев: `xemat.monte_carlo.run_monte_carlo`.
Обёртка для результата обычного расчёта: `run_from_results`.
Для воспроизводимости JSON содержит seed, тип RNG, версии NumPy/SciPy,
исходную модель, смесь и настройки весов. Побитовую повторяемость между
разными версиями библиотек предполагать не следует.
