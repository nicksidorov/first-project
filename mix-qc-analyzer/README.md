# MIX QC 1.1

Переносная версия однофайлового скрипта `pipp.py` для обработки QC-спектров МИКС.
Интерфейс PyQt5, расчёты NumPy/SciPy, Excel через openpyxl и pandas,
необязательные интерактивные HTML-графики Plotly.

## Работа с программой

[Скачать MIX QC 1.1 для Windows](https://github.com/nicksidorov/first-project/releases/download/mix-qc-v1.1.0/MIX-QC-1.1-Windows-x64.zip)

Это отдельный релиз **1.1.0**, с именем EXE `MIX_QC_1.1.exe`.
[Предыдущая версия 1.0](https://github.com/nicksidorov/first-project/releases/tag/mix-qc-v1.0.0)
остаётся доступной; архивы можно распаковать в разные папки и использовать рядом.
Версия указана в заголовке окна и на листе «Информация» в Excel.

Сборка предназначена для Windows 10/11 x64. Распакуйте архив и запустите
`MIX_QC_1.1.exe`. Устанавливать Python и Excel для расчёта и создания XLSX не нужно.
Для просмотра XLSX потребуется Excel или другое совместимое приложение.

1. **Reference spectrum**: выберите шаблонный `.PHD`.
2. **Folder**: выберите папку с измерениями `.PHD`/`.phd`.
3. **Save beta fitting plots / Бета-подгонка** и **Save gamma spectra / Гамма-спектры**:
   независимо включите нужные HTML-графики. По умолчанию включена бета-подгонка.
4. **Use Poisson MLE (iterative reweighting)**: включить IRLS.
5. **Ba (~81 кэВ): диапазон каналов**: по умолчанию 28–36 включительно.
   Можно выбрать другой диапазон в пределах 0–255, не менее 6 каналов для
   подгонки пяти параметров. В диапазон должны попасть пик и фон с обеих сторон.
6. **Run calculation**: выберите файл для Excel-отчёта и дождитесь расчёта.

Отчёт сохраняется по выбранному пути. Графики — рядом, в папке
`<имя отчёта>_plots`. Они открываются в обычном браузере без интернета.
Галочки и выбор файлов блокируются на время работы; закрытие окна во время
активного расчёта требует дождаться его завершения.

Обрабатываются файлы непосредственно в выбранной папке, без вложенных папок.
Если шаблон лежит в этой папке, он также попадёт в список измерений — как в
исходном скрипте. Исходные измерения не изменяются и не передаются в сеть.

## Гамма-графики и FWHM Ba в версии 1.1

Файл `<спектр>_gamma.html` показывает все 256 каналов, подгонки Cs-137
(662 кэВ) и Ba (~81 кэВ), их центроиды и линейные фоны пунктиром. Кривые
подгонки рисуются только внутри соответствующих диапазонов. Можно выделить
область мышью, приблизить колесом и вернуть полный вид двойным щелчком.
Шаблон используется для бета-подгонки; для подгонки гамма-пиков он не нужен.
Рабочий процесс программы по-прежнему начинается с выбора бета-шаблона.

Для Ba используется гауссиана + линейный фон с весами `sigma = sqrt(y+1)`.
Ширина **гауссовой составляющей над фоном**:
`FWHM = 2·sqrt(2·ln(2))·abs(sigma_peak)`, погрешность — тот же множитель,
умноженный на погрешность `sigma_peak` из ковариационной матрицы (1σ).
Метка полувысоты учитывает наклон фона. Если точки полувысоты выходят
за выбранный диапазон, график и Excel предлагают проверить диапазон.
Ось X, центроиды, FWHM и их погрешности выражены **в каналах**;
энергии 81 и 662 кэВ служат обозначениями пиков, калибровка не выполняется.

Ba рассчитывается даже при отключённых графиках. В основной таблице Excel
после прежних десяти столбцов добавлены центроид Ba, его погрешность,
FWHM, погрешность FWHM, границы диапазона и статус. Лист «Гамма-пики»
содержит результаты для всех входных файлов, включая файлы с неудачной
бета-подгонкой. При неудачной гамма-подгонке значения остаются пустыми,
рядом записывается причина; доступный спектр всё равно можно сохранить.

## Сохранённая численная схема

- Матрица `#Histogram` размером 256×256; исключаются `y < 40` и `x + y < 190`.
- Бета-шаблон берётся из проекции отфильтрованной матрицы совпадений по оси 0.
  Отдельный блок `#b_Spectrum` в этом алгоритме не участвует.
- Сглаживание LOWESS и интерполяция CubicSpline с исходными параметрами:
  bandwidth=0.19, poly_order=2, it=3.
- Модель бета-проекции: `A/k * template(x/k)`, каналы 9–220 включительно.
- Фиксированные веса: `sigma = sqrt(max(y, 1))`.
- Пуассоновское перевзвешивание IRLS: на каждой итерации пересчитываются
  предсказания `mu`, используются `sigma = sqrt(max(mu, 1e-10))`, затем
  повторно вызывается `curve_fit`. До 50 итераций, порог 1e-6, как в исходнике.
- Гамма-пик в каналах 209–251: гауссиана + линейный фон; его подгонка остаётся
  с `sigma = sqrt(y + 1)` независимо от галочки IRLS.

**Галочка IRLS относится к бета-подгонке по шаблону**, а не к гамма-пику.
Модель, исходные численные параметры и алгоритм оценивания погрешностей сохранены.
Достижение лимита итераций не подтверждает сходимость: оно отмечается в журнале
и отдельном столбце Excel «Сходимость IRLS». При ошибке внутренней подгонки
файл попадает на лист неудачных результатов. Первые девять столбцов основной
таблицы Excel сохраняют исходный порядок.

## Исправления для переносной версии

- Явный выбор пути Excel вместо записи в текущую рабочую папку.
- HTML сохраняется рядом с отчётом, а не в служебной временной папке EXE.
- Поддержка нижнего регистра `.phd`, сортировка файлов.
- Проверка размера и допустимых значений матрицы; чтение UTF-8/Windows-1251.
- Чтение последней короткой строки гамма-спектра. Повреждённый гамма-блок
  не дополняется нулями и не продолжается данными следующей секции.
- Исправлена диагностика сходимости IRLS без изменения формулы перевзвешивания.
- Защита от закрытия окна и повторного запуска во время активного потока.

Исходный LOWESS оставлен без изменения численной схемы. В нём робастные веса
сбрасываются в начале каждого прохода, поэтому вычисленные между проходами
веса фактически не используются на следующем проходе. Это отдельный вопрос
методики, который следует разбирать при последующем моделировании.

## Проверки

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python pipp.py --self-test smoke.json
```

Проверка окна использует искусственные данные, выполняет оба режима подгонки
и все четыре сочетания галочек бета/гамма-графиков,
создаёт и повторно читает XLSX, сохраняет автономные HTML, обрабатывает
отсутствующий гамма-блок и повреждённую матрицу, проверяет FWHM известного
пика и изменение диапазона Ba. На Windows собранный EXE
проверяется с Python, убранным из PATH, и из папки с кириллицей и пробелом.
Это проверка переноса программы, а не независимая валидация методики QC.
Оценки смещения, разброса и покрытия погрешностей требуют отдельного моделирования.
Реальные пользовательские PHD-файлы в проект и дистрибутив не включаются.

## Сборка

На Windows с Python 3.12 x64:

```powershell
.\build_windows.ps1
```

Создаётся отдельное окружение `.build-venv`, устанавливаются закреплённые
версии зависимостей, запускаются тесты и PyInstaller. Результат:
`dist/MIX_QC_1.1.exe`. Готовый EXE включает библиотеки и временно распаковывает
их при запуске. Научные библиотеки делают эту сборку больше простого просмотрщика.
Qt WebEngine и Chromium для данного скрипта не нужны.

GitHub workflow `.github/workflows/mix-qc-portable.yml` запускается только вручную.
После успешных проверок он публикует переносной ZIP в отдельном релизе `mix-qc-v1.1.0`.
Исходники других программ в репозитории не изменяются.
