# XeMat

Оконное Python-приложение для совместной обработки SAMPLE и предшествующего
GASBK. Матрицы строятся из **Rs/Rg в constants.py и трёх спектров**.
Отдельный режим принимает подготовленную модель NPZ.
Вычисления основаны на предоставленной автором статье `XeMat_RU_MASTER_BAYES_V59.tex`.

Сохранены PyQt5, оформление старого интерфейса и IMS-парсер. В модуль констант
добавлены отдельные калибровки детекторов 221 и 222.
Старый проект помещён в `legacy/` для сравнения и не вызывается новым ядром.

## Запуск

Python 3.10 или новее, Windows/Linux/macOS:

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate
python -m pip install -e ".[test]"
python project.py
```

Если Python установлен через Anaconda, откройте **Anaconda Prompt**:

```bat
conda activate xemat
cd /d D:\Xemat2
python -m pip install -e .
python project.py
```

Окружение `xemat` создаётся один раз: `conda create -n xemat python=3.12 -y`.
Замените `D:\Xemat2` своим путём к папке с `project.py`.

В окне выберите режим **«Матрицы из constants.py»**, укажите SAMPLE,
предшествующий GASBK и DETBK, выберите один из четырёх методов и нажмите
**«РАССЧИТАТЬ»**. NPZ для этого режима не нужен. Используются семь ROI
`[1,2,3,5,6,7,8]`; по умолчанию границы берутся из `FIXED_ROI_TABLE`.
Номер детектора считывается из `#Header 3` (например, `MIX58_221`). Для 221
выбираются `Rs_221/Rg_221`, для 222 — `Rs_222/Rg_222` из `constants.py`.
Номера SAMPLE, GASBK и DETBK должны совпадать. При несовпадении, отсутствии
номера или неизвестном детекторе окно показывает предупреждение с номерами
файлов и останавливает расчёт. Проверка действует также для NPZ с тремя спектрами.
Режим **«Готовая модель NPZ»** сохранён для демонстрации и своих матриц.
В нём можно использовать готовые `x,b` или заменить их тремя IMS-файлами.

В двух таблицах активностей красноватая заливка отмечает обнаруженные изотопы:
свободная оценка `a_c > L_C`. При смене метода, галочки фиксированных ROI
или фиксированных эффективностей
таблицы сохраняют предыдущий расчёт до нажатия **«РАССЧИТАТЬ»**; над ними
появляется пояснение. До нового запуска можно сохранить показанные результаты
с прежними настройками. При выборе других файлов результаты сбрасываются.

Под таблицами активностей показаны настройки ROI, источник эффективностей,
координаты параметров и качество подгонки: **χ²/ν** для МНК/NNLS или
**D/ν** (приведённый пуассоновский девианс) для ММП. Там же указано число
степеней свободы. Около 1 — ориентир при достаточных отсчётах; для методов
с неотрицательностью нормировка обозначена как номинальная. При `ν≤0`
выводится прочерк. Те же показатели входят в текстовый отчёт.

Кнопка **«Сохранить результаты в файл»** сохраняет текстовый отчёт с выровненными
таблицами: условия измерений, отсчёты ROI, параметры пробы и памяти, активности
с ±σ, пороги L_C/MDC и корреляционные матрицы Пирсона для активностей
и параметров пробы/памяти. Активности указаны в Бк и Бк/м³,
таблица L_C/MDC — в мБк/м³. Подробные матрицы находятся в конце отчёта.
Знак `—` означает, что величина не рассчитана или не определена.
[Пример отчёта на синтетических данных](examples/demo_wls_report.txt).
Для выравнивания колонок открывайте TXT в VS Code или Блокноте с моноширинным
шрифтом, например Consolas.

Для встроенной калибровки нужны времена измерений SAMPLE/GASBK, живое время
DETBK, даты пробоотбора, объём извлечённого ксенона в см³ и эффективности
четырёх изотопов Xe. По умолчанию эффективности берутся из SAMPLE и GASBK.
Флажок **«Фиксированные эффективности»** заменяет их массивами
`FIXED_EFFICIENCIES_SAMPLE[номер_детектора]` и
`FIXED_EFFICIENCIES_GASBK[номер_детектора]` в `constants.py`.
Порядок четырёх чисел: **Xe135, Xe133, Xe131m, Xe133m** (ROI 2, 3, 5, 6).
Это ε в долях от 0 до 1, без branching; программа сама умножает ε на BR.
Для 221 начальные значения обоих массивов: `[0.2057, 0.3140, 0.2580, 0.2580]`,
из присланной пары за март 2026. Для 222 значения пока `np.nan`: перед
использованием фиксированного режима заполните оба массива своей калибровкой.
После изменения `constants.py` перезапустите приложение. В отчёт записываются
источник и использованные значения ε. Флажок выключен по умолчанию и недоступен
в режиме NPZ, где чувствительности уже включены в готовые матрицы.

Пропущенные или недопустимые эффективности не заменяются нулями или другим
источником. Если ε берутся из файлов, их опорные области должны совпадать с
калибровкой `constants.py`, в том числе при включённых фиксированных ROI.
Фиксированные ε относятся к `FIXED_ROI_TABLE`: при включении обоих флажков
границы и эффективности из файлов заменяются; при отключении фиксированных
ROI проверяется соответствие границ из файлов калибровке.
Эффективности GASBK относятся к памяти; отдельно от SAMPLE
учитывается отношение чувствительностей Xe133/Xe133m. Объём воздуха
вычисляется по статье: `V0 = V_Xe / 0.087`.

По согласованию с автором сохранено **приближение радона старого проекта**:
эффективность 0,3 и поправка по распаду родительского Rn222. Оно явно указано
в результатах и влияет на перенос памяти. Это не отдельная калибровка
радоновой цепочки, предусмотренная статьёй. Можно задать калиброванные
коэффициенты радона; детали в [docs/mathematics.md](docs/mathematics.md).

В экспериментальной ветке после обычного расчёта доступна кнопка
**«Монте-Карло: Lc / Ld…»**. В отдельном окне выберите изотоп, семейство
методов, число повторов и seed. Модуль разыгрывает пуассоновские отсчёты
SAMPLE/GASBK и заново рассчитывает LC в каждом повторе. Проверяются ложные
обнаружения при A=0 и мощность при A=MDC исходного расчёта, с 95%-ми биномиальными
интервалами, учётом ошибок и сохранением TXT/JSON. Фон DETBK и калибровка
фиксированы. Описание и точный контрольный пример — в
[docs/monte_carlo.md](docs/monte_carlo.md).
Версия до экспериментов сохранена меткой `stable-before-experiments-2026-10-15`.

Для демонстрации с синтетическими, **не калибровочными** данными:

```bash
python -m examples.make_demo
python -m xemat.cli examples/demo_model.npz --method wls --output demo_results.json
python -m pytest
```

Допустимые методы CLI: `wls`, `nnls`, `poisson`, `poisson_nonnegative`.
Безголовый запуск окна для технической проверки: `QT_QPA_PLATFORM=offscreen`.
Результаты проверок и ограничения перечислены в [docs/validation.md](docs/validation.md).

## Подготовленные данные

[Формат NPZ и математика](docs/mathematics.md) описывает координаты, веса,
формулы и соответствие переменных статье. Пример формирования файла находится
в [examples/make_demo.py](examples/make_demo.py).

Минимальные поля: `M`, `x`, `b`, целочисленный `n_sample_parameters`, строка
`coordinates`. Вместо `M` можно передать `R_c,R_g1,R_g2,F`.
Для ограничения физических параметров при `coordinates='beta_gamma'` нужна
`T_c`. Для активностей в детекторе нужна `H`; для MDC — физические координаты
и явный список `mdc_component_indices` (индексы ксенона с нуля).

## Структура

- `xemat/model.py`: модель, совместная матрица и координатные преобразования.
- `xemat/calibration.py`: построение физических матриц по статье из Rs/Rg и метаданных IMS.
- `xemat/detectors.py`: проверка номеров детекторов и выбор доступной калибровки.
- `xemat/solvers.py`: четыре метода, численная диагностика и свободные ковариации.
- `xemat/diagnostics.py`: приведённый χ² и пуассоновский девианс, степени свободы.
- `xemat/activities.py`, `xemat/detection.py`: активности, неопределённости, MDC.
- `ims_parser.py`, `constants.py`: исходный парсер и константы с калибровками 221/222.
- `process_measurement.py`: связь спектров, калибровки/подготовленной модели и расчётов.
- `project.py`, `results_saver.py`: окно и отчёт результатов.

Для реального измерения требуется проверенная калибровочная модель и исходные
спектры. В старом архиве есть текстовый отчёт, но нет соответствующих исходных
файлов, поэтому он не является воспроизводимым контрольным примером нового ядра.
MDC использует нормальное приближение статьи; подтверждение частот ошибок на
низких отсчётах требует отдельного исследования Монте-Карло.
